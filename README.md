# تمام برو

منصة مكتب محاسبة واستشارات بالعربية: مراجعة، استراتيجية، حوكمة، دراسات جدوى، محاسبة قضائية، مهام، ودفتر مقهى.
تعمل بخادم **Node.js + PostgreSQL** بدل تخزين المتصفح، فتُحفظ البيانات مركزياً ويصل إليها كل المستخدمين.
يتطلب PostgreSQL تشغيل **Docker Desktop** على جهازك (محلياً) أو قاعدة بيانات مدارة (سحابياً).

## التشغيل

```bash
npm install
# قاعدة بيانات PostgreSQL محلية عبر Docker (مرة واحدة تبقى تعمل في الخلفية):
docker compose up -d db
export DATABASE_URL=postgres://erp:erp@127.0.0.1:5432/erp
npm start            # http://localhost:3000
```

أول زيارة تعرض صفحة إنشاء **حساب مالك المنصة**. بعدها يضيف المالك بقية الحسابات من `/admin.html`.
الدخول موحّد: حساب المنصة هو الهوية الوحيدة، ويُنشأ تلقائياً حساب الأقسام المقابل له عند أول دخول. المالك يمنح العضو الأقسام من صفحة «المستخدمون» داخل تمام برو (العضو الجديد لا يرى أقساماً حتى يمنحه المالك ذلك).

Docker (التطبيق وقاعدة البيانات معاً): `docker compose up -d --build` (البيانات في الوحدتين `erp-data` و`pg-data`).

### تشغيل على جهازك مع رابط عام مجاني

1. ثبّت Node 22 وDocker Desktop (https://www.docker.com/products/docker-desktop/) وcloudflared (ويندوز: `winget install Cloudflare.cloudflared`، ماك: `brew install cloudflared`).
2. `npm install` ثم `npm run share`. يشغّل الأمر قاعدة بيانات PostgreSQL محلية عبر Docker تلقائياً إن لم يكن `DATABASE_URL` مضبوطاً.
3. يطبع الأمر رابطًا مثل `https://xxxx.trycloudflare.com`؛ شاركه مع من تريد. البيانات تُحفظ في حاوية Docker (الوحدة `pg-data`) على جهازك، والرابط يتغيّر في كل تشغيل ويتوقف بإغلاق النافذة.

### مشاركة عبر شبكة الواي فاي المحلية فقط (بلا إنترنت)

أنشئ ملفاً فارغاً باسم `data/lan.txt` (أو اضبط المتغير `LAN=1`)، ثم شغّل المنصة كالمعتاد. يطبع الطرفية رابطاً مثل `http://192.168.x.x:3000` يعمل فقط لأي جهاز على نفس شبكة الواي فاي (لا يحتاج إنترنت ولا cloudflared)، وهذا أكثر أماناً من الرابط العام لأنه لا يُقرأ خارج شبكتك.

### تشغيل دائم على جهاز ويندوز

1. ثبّت Node 22 وDocker Desktop (ثبّته وشغّله مرة قبل المتابعة)، وcloudflared فقط إن أردت رابطًا عامًا، وفكّ ضغط المشروع.
2. انقر مرتين على `scripts\windows\install.bat`. يثبّت الاعتماديات وينشئ اختصار تشغيل تلقائي في مجلد Startup وتعيد التشغيل إن توقف الموقع، ويمنع سكون الجهاز أثناء الشحن.
3. تفتح المنصة وحدها على `http://localhost:3000` ويظهر اختصار `TamamPro` على سطح المكتب. دون cloudflared تعمل على هذا الجهاز فقط. معه اقرأ الرابط العام من `data\public-url.txt`. هذا رابط مؤقت يتغيّر عند كل إعادة تشغيل.
4. للتحديث: انقر مرتين على `scripts\windows\update.bat` (لا يمس مجلد data). للإيقاف: `scripts\windows\uninstall.bat`. السجل في `data\server.log`.
5. يلزم أن يكون Docker Desktop مفتوحاً (أو مضبوطاً للتشغيل عند بدء ويندوز) حتى تعمل قاعدة البيانات المحلية.

**رابط ثابت على نطاقك (مثل tmam.pro):** انقل سيرفرات أسماء النطاق إلى Cloudflare (مجاني)، ثم من Zero Trust > Networks > Tunnels أنشئ نفقًا من نوع cloudflared، وأضف Public Hostname للنطاق يشير إلى `http://localhost:3000`، وانسخ الرمز (token) إلى الملف `data\tunnel-token.txt`، ثم أعد تشغيل المهمة. بعدها يعمل الموقع على نطاقك بشهادة HTTPS ما دام الجهاز شغّالًا ومتصلًا بالإنترنت.

### نشر برابط عام (Render)

1. ادمج الفرع في `main`، ثم من Render: **New > Blueprint** واختر المستودع (يقرأ `render.yaml`). ينشئ تلقائياً قاعدة بيانات PostgreSQL مدارة (`tamam-pro-db`) ويربط `DATABASE_URL` بها.
2. أدخل `ANTHROPIC_API_KEY` إن أردت المساعد الذكي (اختياري).
3. بعد النشر افتح الرابط الذي يعطيك إياه Render؛ أول زيارة تنشئ حساب المالك، فأنشئه فورًا.

**خطة مجانية:** استخدم `render.free.yaml` (حقل Blueprint Path). قاعدة بيانات Render المجانية تُحذف تلقائياً بعد 30 يوماً، والخدمة بلا قرص دائم فتضيع النسخ الاحتياطية المحلية عند كل إعادة نشر أو تشغيل وتنام الخدمة بعد 15 دقيقة، وتصلح للتجربة فقط.

القرص الدائم (`/data`) يحفظ النسخ الاحتياطية فقط (قاعدة البيانات نفسها في خدمة Postgres المدارة)، ويتطلب خطة مدفوعة. يصلح أي مزوّد آخر يدعم Docker مع PostgreSQL وقرص دائم.

| متغير | الافتراضي | الوصف |
|---|---|---|
| `PORT` | 3000 | المنفذ |
| `DATABASE_URL` | — | رابط اتصال PostgreSQL (مطلوب) |
| `COOKIE_SECURE` | 0 | اجعله 1 خلف HTTPS |
| `TRUST_PROXY` | 0 | اجعله 1 خلف وكيل عكسي |
| `ANTHROPIC_API_KEY` | — | يفعّل المساعد الذكي في قسم المراجعة (المفتاح يبقى على الخادم) |
| `ANTHROPIC_MODEL` | `claude-sonnet-5-5` | نموذج المساعد |
| `BACKUP` | 1 | نسخ احتياطي تلقائي عند التشغيل ثم كل 24 ساعة (0 للإيقاف) |
| `BACKUP_DIR` / `BACKUP_KEEP` | `data/backups` / 14 | مجلد النسخ وعدد النسخ المحفوظة |

فحص الصحة: `GET /healthz`.

## المعمارية

- `public/`: واجهة الموقع الأصلية (الغلاف `index.html` + 7 أقسام) دون تغيير تصميمها.
- `public/claude-shim.js`: يوفّر `window.claude.use('db' | 'user' | 'downloads')` الذي تعتمد عليه الأقسام، ويتصل بالخادم (قاعدة مستندات بأسلوب Firestore، تحديث فوري عبر SSE).
- `server/`: خادم Express، مخزن مستندات فوق PostgreSQL، حسابات المنصة (scrypt) وجلسات HttpOnly وتقييد محاولات الدخول.
- `public/vendor/`: المكتبات والخطوط محلية (لا اعتماد على الإنترنت). لإعادة توليدها: `npm install && npm run vendor`.

## الاختبار والنسخ الاحتياطي

```bash
npm test            # اختبارات الخادم
npm run backup      # نسخة متسقة إلى data/backups
```

## حدود معروفة

- المساعد الذكي لا يظهر إلا مع وجود `ANTHROPIC_API_KEY`، وحدّه 20 طلباً في الدقيقة لكل مستخدم.
- حسابات الأقسام التي تُضاف يدوياً من صفحة «المستخدمون» لا تستطيع الدخول؛ أضف المستخدمين من `/admin.html`.
- أي مستخدم مسجّل في المنصة يستطيع تقنياً قراءة بيانات المكتب كلها عبر الواجهة البرمجية؛ فصل الصلاحيات الحالي يتم داخل واجهة كل قسم. أضف حسابات للموثوقين فقط.
