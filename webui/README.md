# واجهة الويب لنظام ERP (عربية RTL)

واجهة متصفح فوق قاعدة Oracle: كل المنطق المحاسبي في حزم PL/SQL (`oracle/`)، والواجهة تستدعيها فقط (Express + node-oracledb بوضع thin، لا يلزم Oracle Client).

## ما يعمل الآن
- **المحاسبة:** دليل الحسابات (إضافة/تعديل اسم/إيقاف)، قيد يومية جديد (مؤشر توازن فوري)، دفتر اليومية مع العكس.
- **التقارير:** ميزان المراجعة، كشف حساب، قائمة الدخل، الميزانية، التدفقات النقدية، طباعة.
- **الإقفال:** إقفال/فتح الشهر مع فحص الملاحظات، إقفال/فتح السنة.
- **المبيعات والمشتريات:** العملاء والموردون وكشف حساب كل طرف، فواتير المبيعات والمشتريات (بنود حرة أو أصناف مخزنية تحرّك المخزون وتُرحَّل تكلفتها)، سندات القبض والصرف (على فاتورة أو دفعة على الحساب)، إلغاء الفاتورة غير المسدّدة، أعمار الديون.
- **المخزون:** الأصناف (إضافة، سعر وضريبة، إيقاف)، المخازن، أرصدة بالمتوسط المرجّح مع مطابقة الأستاذ، حركات المخزون، تسوية جرد/رصيد افتتاحي، تحويل بين المخازن.
- **الأصول الثابتة:** سجل الأصول مع مطابقة الأستاذ، أصل جديد وفئات، تشغيل الإهلاك الشهري وعكسه، بيع/استبعاد الأصل، إلغاء أصل لم يُهلك، جدول إهلاك كل أصل.
- **الرواتب والموارد البشرية:** الموظفون والأقسام وتاريخ الراتب وإنهاء الخدمة، مكوّنات الراتب (نسب وسقوف تعرّفها أنت)، التسويات الشهرية، السلف، كشوف الرواتب (إنشاء/حساب، ترحيل، صرف، إلغاء).
- **نقاط البيع:** شاشة كاشير (باركود أو بحث، خصم %، دفع نقدي/بطاقة/مختلط، باقي)، ورديات وإقفالها بفرق الصندوق، إيصال، مرتجع جزئي، إلغاء عملية، تعريف النقاط. ماسح الباركود (لوحة مفاتيح) يعمل بالكتابة في خانة الباركود.
- **أوامر الشراء:** إنشاء (بنود أصناف أو بنود حرة)، اعتماد، استلام كلي أو جزئي بسعر فاتورة المورد الفعلي (ينشئ فاتورة مشتريات ويُدخل المخزون)، إلغاء الاستلام، إغلاق ما تبقى، إلغاء الأمر.
- **عروض الأسعار:** إنشاء، إرسال، قبول/رفض، عرض معدَّل، تحويل إلى فاتورة مبيعات وإلغاء التحويل، إنهاء العروض المنتهية، نسبة التحويل. **إعدادات الضوابط:** حد اعتماد الأوامر وأعلى خصم للعروض.
- لا شاشة لتعديل بنود مسودة أمر/عرض بعد الحفظ (الواجهة البرمجية جاهزة `PUT /api/po/:id/lines`): الحل الآن إلغاء المسودة وإنشاؤها من جديد.
- **الضريبة السعودية (ضريبة القيمة المضافة):** النسبة الافتراضية 15% تُملأ في بنود الفواتير والعروض والأوامر والأصناف (قابلة للتغيير لكل بند)، إعدادات المنشأة والرقم الضريبي، ترويسة فاتورة ضريبية/مبسطة مع رمز QR (المرحلة الأولى من الفوترة الإلكترونية؛ صيغة TLV/Base64 مطابقة لمثال هيئة الزكاة والضريبة والجمارك) على فواتير المبيعات وإيصالات نقاط البيع، وتقرير إقرار الضريبة (مخرجات مقابل مدخلات حسب النسبة، ويطابق ح/2200).
  - **غير مغطّى:** الربط مع منصة فاتورة (المرحلة الثانية: شهادات وإرسال إلى الهيئة)، وتصنيف الصفرية/المعفاة/خارج النطاق كأنواع منفصلة، وإشعارات الدائن/المدين كمستندات مستقلة (الإلغاء بقيد عكسي)، والزكاة وضريبة الاستقطاع، وتأمينات GOSI في الرواتب.
  - **وقت QR:** يُستخدم تاريخ الفاتورة بوقت 00:00:00Z لأن النظام لا يحفظ وقت الإصدار.
  - مكتبة رمز QR: `public/js/vendor/qrcode.js` (qrcode-generator، ترخيص MIT).
- **الإعدادات والمستخدمون والصلاحيات:** مركز «إعدادات النظام»؛ مستخدمون بأسماء وكلمات سر مشفّرة (scrypt) وأدوار؛ سبعة أدوار جاهزة (مدير النظام، محاسب، مبيعات، مشتريات ومخازن، كاشير، موارد بشرية ورواتب، مشاهدة فقط) ومصفوفة صلاحيات قابلة للتعديل (لا شيء / قراءة / قراءة وكتابة لكل وحدة) وإنشاء أدوار مخصصة؛ تعطيل المستخدم أو تغيير كلمة سره يُسقط جلساته فوراً؛ سجل عمليات (من فعل ماذا ومتى)؛ تغيير كلمة السر الشخصية.
  - **التفويض في الخادم:** كل طلب يُفحص حسب الوحدة (GET = قراءة، وغيره = كتابة)؛ ما لا يطابق قاعدة يُمنع لغير المدير. إخفاء القوائم في الواجهة للراحة فقط.
  - **المدير الأساسي** (من `.env`: ERP_WEB_USER/ERP_WEB_PASSWORD) لا يُعطَّل ولا يُحذف وصلاحياته كاملة؛ هو مخرج الطوارئ.
  - **الجداول** `WEB_USERS` و`WEB_ROLES` و`WEB_AUDIT` تُنشأ تلقائياً عند تشغيل الواجهة، بلا بادئة ERP_ فلا يحذفها `uninstall.sql` ولا إعادة التثبيت.
  - **حدود:** المستوى على مستوى الوحدة كاملة (التجارة تشمل العملاء والموردين معاً)؛ لا فصل مهام «أنشأه/اعتمده» بين مستخدمي الواجهة (يظهر الحساب المشترك ERP_OWNER داخل القاعدة)؛ لا مصادقة ثنائية ولا قفل حسابات (يوجد حد 5 محاولات/10 دقائق لكل عنوان).
- كل أقسام النظام صار لها شاشات ويب.

## التشغيل على ويندوز (بدون تثبيت Node) — الأسهل
بعد تثبيت قاعدة البيانات (`oracle\local\install-local.ps1`) وأن حاوية Oracle تعمل:
```powershell
cd webui
powershell -ExecutionPolicy Bypass -File .\run-docker.ps1
```
يطبع كلمة سر الدخول (تُحفظ في `webui\.env-docker`) ثم افتح http://localhost:3001 (المستخدم `admin`).

لينكس/ماك: `./run-docker.sh`.

## التشغيل المباشر (Node 18+)
```bash
cd webui && npm install && npm run init && npm start
```
`npm run init` ينشئ `.env` (كلمة سر القاعدة من `oracle/local/.env`) ويطبع كلمة سر الدخول.

## الإعدادات (`.env`)
`ERP_DB_USER` · `ERP_DB_PASSWORD` · `ERP_DB_CONNECT` (الافتراضي `localhost:1521/XEPDB1`) · `ERP_WEB_PORT` (3001) · `ERP_WEB_HOST` (الافتراضي 127.0.0.1) · `ERP_WEB_USER` · `ERP_WEB_PASSWORD` · `ERP_WEB_SECRET` · `ERP_COOKIE_SECURE=1` عند HTTPS.

## الأمان — اقرأ قبل فتحها على شبكة
- مستخدمون بأدوار وصلاحيات على مستوى الواجهة والخادم، لكن الاتصال بالقاعدة بحساب `erp_owner` واحد (راجع قسم الإعدادات والصلاحيات).
- يستمع الخادم على 127.0.0.1 فقط افتراضياً. لا تفتحه على الإنترنت دون HTTPS ووكيل عكسي.
- الجلسة بكوكي موقّع HttpOnly/SameSite=Strict، الطلبات الكاتبة JSON فقط، ترويسة CSP، وحد 5 محاولات دخول فاشلة/10 دقائق لكل عنوان.

## الاختبار
`npm test` (تكاملي على قاعدة حقيقية؛ يُتخطى دون كلمة سر القاعدة). لإضافة اختبارات الكتابة (ترحّل قيوداً فعلية): `ERP_TEST_WRITE=1 npm test`.

## ما اختُبر
جُرّبت على Oracle XE 21c: واجهة API (19 اختباراً)، ومتصفح Chromium (دخول، قيد، دفتر، التقارير، الفترات)، وصورة Docker تتصل بالقاعدة عبر `host.docker.internal`. لم يُجرَّب `run-docker.ps1` على ويندوز فعلياً، ولا `npm ci` داخل بناء Docker في بيئتي (حُجب الوصول للسجل).
